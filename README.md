# Crychic

以 [MoviePilot](https://github.com/jxxghp/MoviePilot) 为后端的聊天机器人，在 Telegram 中搜索影视并创建订阅。交互流程参考 [Doplarr_rs](https://github.com/activexray/doplarr_rs)。

当前范围：Telegram、订阅与选种下载、白名单权限。Discord 计划中。

## 使用

私聊直接发送片名即可搜索。和 MoviePilot 自带的机器人一样，片名前可以加「订阅」「搜索」或「下载」（后面跟空格或冒号也行，比如 `下载：沙丘`）：前两个和直接发片名一样；「下载」在你选定电影或某一季后直接开始搜索资源，跳过订阅确认，结果页的「返回」回到那张卡片。`/search` 后面同样可以带这些前缀。`/start` 打开首页，所有功能都有入口；也可以直接用命令：

```
/search 沙丘
```

正在等待起始集数时，普通文字优先作为回答，支持 `5`、`５`、`第5集` 等写法；发送 `/search 新片名`、`/start`、`/trending` 等有效命令会清除旧提问并切换流程。群聊仍通过命令操作，输入回答时需要引用机器人的问题。

群聊中明确发给其他机器人的命令不会被 Crychic 接管。话题群里的回复、输入提示和入库通知会留在原话题；设置了独立通知频道时，入库通知仍按配置发到频道。

所有页面的按钮遵循同一套约定：最后一行是导航。「返回」回到上一屏；从列表（搜索结果、榜单、相似推荐、同系列）里选中再订阅或下载的，完成后的消息也有「返回」，直接回到选片的那一页接着逛；「取消」结束正在进行的搜索、订阅或下载；浏览类页面（订阅、任务、榜单、追剧日历、最新入库）用「首页」回到首页、「关闭」收起消息。删除、取消订阅这类不可撤销的操作会先单独确认。

选择搜索结果 → （剧集）选择季和起始集 → 确认订阅。已订阅的媒体会提前结束流程，暂停中的订阅会明确标出“目前已暂停”，不会自动恢复。剧集也可以点「多选季…」一次勾选多季，每季从第 1 集开始订阅，已在订阅中的季会跳过（仍会通知）。

搜索结果每页最多 8 条，可翻页查看全部返回结果；选片后返回会恢复原来的页。只有一个结果时直接打开媒体卡片，只有一个常规季且没有特别篇时省去选季，但最终订阅仍需确认。点「重新搜索」可以在原消息中换片，旧查询的按钮随之失效；没有结果时可以直接回复新的片名。换名纠错会保留原来的下载意图，显式加“搜索”或“订阅”可以改回普通流程；进入“相似推荐”或“同系列”选择其他作品则先显示普通卡片，需要你主动点“搜索资源”。

搜索、季信息或已有订阅查询失败时，可以在原消息中点「重试」，保留已经选好的媒体和季；也可以重新搜索、返回上一步或取消。重试只重复失败的查询，不会创建订阅。等待输入的请求过期后，私聊直接发送的片名会立即开始新搜索；明确引用旧提问的回答只提示过期。连点确认不会重复提交，也不会把刚显示的成功结果改成过期提示。

订阅被 MoviePilot 明确拒绝时会显示原因。提交后遇到网络或响应异常，或者没有收到有效的订阅 ID，会提示先用 `/subscribe` 核对结果，不自动重发；旧确认按钮也不能再次提交。

机器人会通过 MoviePilot 查询媒体服务器（Emby/Jellyfin/Plex）里已有的内容：已在库中的电影和整季不会重复订阅；季按钮会标出「已入库」或「已有 N 集」，部分入库的季在确认时列出已有的集（MoviePilot 订阅只下载缺少的集）。选定后还会显示下载器里对应任务的进度。

想要更好的版本时，点卡片上的「洗版订阅」：电影确认页、季的起始集选择页，以及已经在媒体库里的电影或整季都有这个入口。确认后 MoviePilot 会按订阅规则的优先级持续寻找更好的版本，下到最高优先级为止，媒体库里已有的也会重新下载；剧集洗版整季，不用选起始集。已经有订阅的媒体不会再新建洗版订阅（MoviePilot 会直接沿用原订阅）；自己的订阅可以在 `/subscribe` 的详情中点「编辑条件」修改洗版模式。每个新版本入库都会通知请求人。

媒体库查询失败时，卡片会显示「媒体库状态暂时无法确认」，仍可手动确认订阅。详情、海报和下载进度不可用时也不会阻断订阅流程。

选定电影或某一季后，卡片上有「搜索资源」，MoviePilot 按媒体来源、ID 和季去各个站点搜种，通常要几十秒，消息会显示等待时间，搜索期间可以随时「取消」。想限定搜索范围，可先点「选择搜索站点」，勾选后点「开始搜索」；不选则使用全部可搜索站点。「筛选站点」只筛选已经返回的资源，不再访问站点。

结果默认按 MoviePilot 的优先级排列，也可以改按做种数、发布时间、大小或站点排序。某一季媒体库里已有部分集数时，资源会标出能补哪些集或「已都有」，「只看缺集」隐藏不补缺的资源；这些操作都在已有结果里进行。每页最多 8 条，点编号看详情，再点「确认下载」。多选可以跨页、换排序和筛选保留，最多 20 个；「下载所选 N 个」会列出资源和总大小，确认后逐个提交并给出回执。站点 Cookie 和下载链接只在内存中转交，不显示或写入日志。下载结果不确定时先用 `/tasks` 核对，机器人不会重发。

配置有效的资源 Cookie 后，搜索结果会逐步出现。早期候选尚未匹配媒体，只能浏览；完整最终结果到齐后才开放下载。流式列表的编号固定对应原资源，排序后可能不连续，重新搜索也不复用旧编号。进入详情会停止自动改页，可点「刷新结果」读取最新状态；被最终结果移除或改变的资源必须返回列表重新选择。断线、认证失败或两分钟总预算耗尽时会标明结果不完整，不自动重连，也不改发一次 JSON 搜索。「重新搜索资源」会再次访问站点。取消或返回媒体卡片会关闭本地流，但无法保证 MoviePilot 已发出的每个站点请求立即停止。

下载的文件入库后会通知请求人，长时间没有进展也会提醒一次。上游集数识别不可靠时，列表和详情标注“集数识别不确定”，不会把整季包误写成单集。补集完成判定会计入登记时媒体库已有的集数；整季已在库后重新下载，仍等待本次文件到达。旧版请求没有保存的历史库存无法自动补回。

批量确认后会立即显示“正在提交 N/M”，逐项通过 MoviePilot API 提交。可点“停止后续提交”：当前一项等待结果或超时，后面的不再提交，已创建的下载不会被暂停或删除。该页面结束前保留进度和停止按钮，仍可发送新命令使用其他功能。这里显示的是提交进度，实际下载百分比请看 `/tasks`。重启不会重放未提交或结果不明的请求，应先用 `/tasks` 核对。

订阅的内容入库后，机器人默认在请求所在的聊天里通知请求人（群聊中会 @ 对方）。设置 `CRYCHIC_TELEGRAM_NOTIFY_CHAT_ID` 后，通知改为只发到指定频道，不再发回请求聊天，也不公开请求人的身份；多人请求同一条订阅时，频道只收到一条通知。它仍然只通知通过 Crychic 请求的内容，不广播整个媒体库。

通知会等到媒体服务器（Emby 等）能看到新文件再发（最多等 `CRYCHIC_NOTIFY_LIBRARY_WAIT`），并在能匹配到观看地址时附上「在 Emby 中观看」链接。

通知按 MoviePilot 的成功整理时间跟踪，失败文件重试成功后也会通知。旧版请求数据会自动迁移，保留待发通知、周报和停机期间新增的整理记录；升级前因旧游标漏掉的低 ID 历史无法可靠地区分是否已通知，不会全量补发。

同一季的连载增加集数时，通知范围会跟随订阅更新。首次到货不会清除仍在订阅中的请求人，因此洗版订阅仍可暂停或取消，后续新版本入库也会通知；普通电影不会因此重复提醒。旧版已经删除的请求记录无法自动恢复。


追剧日历：列出你订阅的剧（TMDB 条目）接下来 7 天（北京时间）要播的集，按日期分组，点编号打开那条订阅的详情，「返回」回到日历，即使那条订阅已经结束。某部剧的播出时间暂时读不到时会在页脚注明。首页的「追剧日历」按钮也能打开；这周没有要播的集时只弹一下提示。

```
/newly_added
```

媒体库最新入库的内容，点片名直接打开媒体服务器网页观看。

```
/trending
```

浏览 TMDB 流行趋势、豆瓣热门电影/剧集、正在热映和新番放送表（按周几分页，默认今天）。选中一部会自动找到对应的 TMDB 条目进入订阅流程（续作如「青之芦苇 第二季」也对得上，直接进第 2 季）；豆瓣/Bangumi 条目对不上时让你在搜索结果里挑。条目搜不到或查询失败时仍可返回原榜单。

```
/subscribe
```

按电视剧、电影分开列出 MoviePilot 的影视订阅（不混入音乐或未知类型）（状态、缺几集），用按钮切换。你通过 Crychic 请求的订阅可以用「取消订阅」选出来取消，取消后不再通知。已结束的订阅在「订阅历史」里，每类显示最近 10 条，可以按原来的设置重新订阅。

点编号打开订阅详情，查看起始集、规格、规则组，以及最近一次搜索的状态和时间（北京时间）。「刷新」重新查询，「返回」恢复原来的订阅列表页，不会触发补搜或下载。你请求的订阅在详情里可以「暂停订阅」（MoviePilot 暂时不再为它找资源），暂停后按钮变成「恢复订阅」；改完会重新读取订阅，显示最新状态；返回列表也会刷新状态并保留原来的类别和页码。MoviePilot 拒绝时转达它的原话，结果不明时提示点「刷新」核对，不会自动重试。

详情把媒体库状态与下载、整理进度分列展示，相同状态的连续集数合并成一行。下载百分比是关联任务的整体进度；整理完成不等于媒体服务器已经可见，MoviePilot 的待获取集数也不等于尚未入库的集数。查询失败显示未知；没有执行记录时不会猜测原因。每次最多展示请求范围内的前 100 集，每页最多 20 行，超出部分明确提示。详情不展示资源名、站点、下载器或文件路径，后台执行错误只提示到 MoviePilot 查看。

### 编辑订阅条件

打开 `/subscribe` → 选择自己请求的订阅 →「编辑条件」。可调整分辨率、资源类型、画面格式、已有规则组、订阅站点、包含与排除关键词、电视剧起始集，以及普通／洗版模式；电视剧还可以选择分集洗版或全集洗版。不创建新规则组，不改变媒体身份、季或剧集组。

所有修改先留在当前会话的草稿里，菜单标出已修改项和未保存项数，字段页显示当前值，点「恢复原值」只撤回当前一项。「查看修改」列出改动，点「确认保存」才会写入 MoviePilot。从字段页返回保留草稿；有改动时，从编辑菜单返回或取消会先询问是否放弃，点「返回」继续编辑，点「放弃修改」才丢弃草稿。无改动则直接离开。重启或会话过期不会保存草稿。

只提交实际改动字段，不覆盖下载器、路径、调度周期、已取得集数、缺集数或现有洗版优先级。保存不会主动补搜；后台后续调度可能按新条件搜索下载。

规则组和站点支持多选、分页，完成选择和返回都会把勾选保留在草稿中。空规则组沿用全局设置，普通订阅与洗版使用各自的全局规则组；空站点选择沿用 MoviePilot 的默认订阅站点。目录读取失败不清空原设置，选中的规则定义或站点变化时保留其他草稿，重新选择变化的目录项后再确认。

包含与排除条件接收**字面关键词**，用 `|` 分隔候选，任一匹配，最多 256 字、12 项。例如 `简体|CHS`；`[Group]`、`.`、`+` 等按原字符匹配，不作为正则运算符。原有后台正则保留但不在聊天中展开；复杂正则继续在 MoviePilot 中维护。不要输入凭据、链接或服务器路径。

保存前重新核对请求归属、媒体身份、创建时间和条件快照。后台条件已经变化时保留草稿，列出差异；同一字段有冲突时，逐项选择「保留草稿」或「采用后台」。点「完成处理」接受最新后台值和保留的草稿，再重新确认保存。未修改的字段沿用后台新值；后台再次变化时重新处理，不自动合并或写入。

保存回执提供「核对结果」，对本次修改逐项显示“已生效”“仍为原值”“已变为其他值”或“暂时无法确认”，包含站点及包含／排除条件。核对只读，不重试写入，也不把结果摘要恢复为草稿。敏感表达式不展示；当前值相同不能证明当时请求一定成功。摘要仅在当前会话内存保留，重启或会话过期后应在 `/subscribe` 或 MoviePilot 后台核对。

这个预检不能代替后端原子比较并写入，预检后仍可能有外部并发修改。编辑后的通知范围会跟随起始集和洗版模式，但不会把略过的集数当作已经入库。

该功能按 [MoviePilot v3.1.1 更新接口](https://github.com/jxxghp/MoviePilot/blob/v3.1.1/app/api/endpoints/subscribe.py#L299-L379)核验；不需要资源 Cookie，也不新增配置项。更旧版本的部分更新和清空语义未验证，不应假定相同。

### 我的请求与异常

```
/requests
```

首页也有「我的请求」。只列出你通过 Crychic 登记的订阅和选种下载，提供「跟踪中」「需留意」「最近完成」三种视图。全局任务和管理员账户下的其他订阅不会自动算作你的请求。点编号查看待获取、下载、整理和逐集媒体库状态；刷新只查询，不补搜、不下载，也不重新整理。

「需留意」包含暂停、搜索执行提示、关联整理失败和暂时无法确认的状态。失败历史每次最多检查最近 100 条，显示已知失败阶段及固定的后台核对建议，不展示原始错误、资源名、实例名或服务器路径。来源读取失败时保留其他成功结果；未匹配到失败记录不代表一定没有异常，旧失败也不代表当前仍在阻塞。同 hash 的下载实例无法确定、季集不明或使用尚未映射的剧集组时，相关进度保持未知。失败历史没有下载器实例字段，同资源记录只提示到后台核对，不冒充本次选种下载的确定异常。

最近完成保存在现有 `requests.json` 中，整个实例最多保留 50 条，再按请求人筛选。只记录功能启用后结算的完整范围，旧记录不自动回填。选种下载必须由该下载的实际到货覆盖所需范围，已有库存不能冒充本次整包完成；洗版和未映射剧集组不据此宣称目标全部完成。完成详情保留当时的季与起始集，但媒体库当前是否可见仍单独查询。订阅关闭、任务消失和整理结束都不等于可播放。

本功能不新增配置，也不要求资源 Cookie。已对照 MoviePilot `v3.1.1` 和 [v3.1.3 源码](https://github.com/jxxghp/MoviePilot/tree/v3.1.3)核对所用接口，两版本契约兼容。版本号仅记录核验范围，运行时不锁版本、不按小版本分支；新增响应字段忽略，可选诊断缺失或未知时局部显示未知。

### 下载任务

```
/tasks
```

列出 MoviePilot 下载中和整理中的任务（只含 MoviePilot 添加的下载）。选中一个任务后，消息会自动刷新进度，直到任务结束、按「停止刷新」或刷新满 10 分钟（可「继续刷新」）；任务页的「返回」会重新读取任务列表，任务全部结束后仍保留“首页”和“关闭”。整理任务显示每个文件的状态，没有百分比。

任务列表分别处理下载、整理的查询结果：一路查询失败仍展示另一路成功结果，并注明暂时无法确认的部分，提供「刷新」。只有两路查询都成功且为空时，才会显示没有任务。

下载任务页有「删除任务」，确认后 MoviePilot 会删除任务**和已下载的文件**。如果同一部片（同一季）还有订阅，确认页会提醒：订阅下的任务删掉后，MoviePilot 已把这些集记为已获取，订阅不会自动重新下载。删除后不再通知这个下载的入库。

会话消息编辑遇到临时投递失败时，会重试尚未显示的结果，包括订阅、下载的成功回执；不会重新执行搜索或写操作。重试最长持续 10 分钟，并遵守 Telegram 的限流等待。接受新的导航后停止旧结果重试。新消息发送结果未知时不会自动重发，避免重复消息。

从白名单移除用户并重启后，旧请求也不再向该用户发送通知；其他请求者和配置的通知频道不受影响。

新番页的身份匹配和简介补充最多共等 5 秒，超时先显示已取得的内容，下次打开继续尝试。简介优先使用 TMDB 和 MoviePilot API，仍为空或失败时才在剩余时间内回退 Bangumi 公共 API；星期分组继续使用完整的 Bangumi 放送日历。

### Inline 模式

在任意聊天的输入框里输入 `@机器人用户名 片名`（至少 2 个字），会弹出带海报的候选列表；选中一条就把一张简短卡片（片名、年份、类型、评分、详情页链接）发到当前聊天，卡片上的「在机器人里打开」会跳到和机器人的私聊，直接打开这部片的卡片，接着订阅或搜资源。只有白名单用户能看到结果。分享出去的卡片是普通 HTML 消息（inline 结果发不了 rich message）。

需要先在 BotFather 里对机器人执行 `/setinline` 开启 inline 模式。

## 配置

全部通过环境变量：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `CRYCHIC_MOVIEPILOT_URL` | 是 | MoviePilot 地址，如 `http://moviepilot:3000` |
| `CRYCHIC_MOVIEPILOT_API_KEY` | 是 | MoviePilot 设置中的 `API_TOKEN`，以超级管理员身份调用 |
| `CRYCHIC_MOVIEPILOT_COOKIE` | 否 | 仅填名为 `MoviePilot` 的资源 Cookie 值；启用资源搜索 SSE。留空保持 API Key JSON 搜索，无自动登录或续期 |
| `CRYCHIC_TELEGRAM_TOKEN` | 是 | BotFather 发放的 Bot Token |
| `CRYCHIC_TELEGRAM_ALLOWED_USERS` | 是 | 允许使用的 Telegram 用户 ID，逗号分隔。陌生人使用时机器人会回复其 ID |
| `CRYCHIC_TELEGRAM_API_URL` | 否 | 自建 Bot API 服务器地址，默认 `https://api.telegram.org` |
| `CRYCHIC_TELEGRAM_NOTIFY_CHAT_ID` | 否 | 入库通知频道，如 `-1001234567890` 或 `@crychic_arrivals`；留空保持原聊天通知 |
| `CRYCHIC_BANGUMI_API_URL` | 否 | Bangumi API 地址，默认 `https://api.bgm.tv`；新番放送按周几读取它的每日放送 |
| `CRYCHIC_DATA_DIR` | 否 | 数据目录，默认 `data`，保存等待入库通知的请求 |
| `CRYCHIC_NOTIFY_INTERVAL` | 否 | 检查入库的间隔，默认 `1m` |
| `CRYCHIC_NOTIFY_LIBRARY_WAIT` | 否 | 入库通知最多等媒体服务器多久，默认 `30m`；`0s` 表示整理完立即通知 |
| `CRYCHIC_PROGRESS_INTERVAL` | 否 | 任务和资源搜索列表的刷新间隔，默认 `5s`；流式首批结果与终态及时显示，中间事件不逐条刷屏 |
| `CRYCHIC_NOTIFY_QUIET` | 否 | 剧集入库的静默期，默认 `3m`：一段时间内没有新集入库后，把这段时间到的集合并成一条通知；`0s` 表示不合并 |
| `CRYCHIC_NOTIFY_DIGEST` | 否 | 每周入库汇总的时间（北京时间），如 `sun 20:00`；留空不发。汇总列出上次汇总以来 MoviePilot 整理进媒体库的所有内容（不论是不是通过机器人请求的），同一部剧同一季合并成一条，能匹配到媒体服务器地址时片名可点；设置了 `CRYCHIC_TELEGRAM_NOTIFY_CHAT_ID` 时发到频道，否则私聊发给每个白名单用户（需要先和机器人私聊过）。第一次启用时从下一个汇总时间开始，重启不会重发，这周什么都没入库时不发 |
| `CRYCHIC_NOTIFY_STALL` | 否 | 下载长时间无进展提醒，默认 `6h`：你请求的剧集或电影对应的下载这么久进度没有变化（手动暂停的不算），就提醒一次（设置了通知频道则发到频道）；每个种子只提醒一次；`0s` 关闭。MoviePilot 只要加了种子就算订阅完成、不再检查进度，所以仍需跟踪进展。MoviePilot v3.1.0 不区分排队和正在下载，提醒会说明可能仍在排队，不断言种子卡死 |

```sh
go build -o crychic ./cmd/crychic && ./crychic
```

### 可选资源 Cookie

由部署者通过受控环境注入 `CRYCHIC_MOVIEPILOT_COOKIE`，只接受单个未加引号的令牌值，不接受 `MoviePilot=...`、整段 Cookie 头、换行或额外 Cookie 项。Cookie 只发到配置源站的资源搜索 SSE 路径，所有重定向都拒绝，不与其他服务共享 Cookie jar。公开域名必须用 HTTPS；私有或回环 IP、Docker 单标签服务名可以使用 HTTP。地址不得带用户名密码、查询参数或片段。

MoviePilot 会校验令牌的资源用途和身份，API Key 或普通登录 JWT 不能改名充当该 Cookie。认证失败时普通 API Key 功能仍可用；管理员安全更新 Cookie 后重启，或移除该变量恢复 JSON 搜索。不要在聊天、日志或提交中粘贴凭据，也不要把真实值写入 compose 示例。依据为 [MoviePilot v3.1.1 认证源码](https://github.com/jxxghp/MoviePilot/blob/v3.1.1/app/adapters/web/security/access.py#L176-L301)。

### 独立通知频道

把机器人添加为目标频道的管理员，并授予发布消息的权限。公开频道可以填 `@频道用户名`，私有频道使用数字频道 ID。

```sh
CRYCHIC_TELEGRAM_NOTIFY_CHAT_ID=-1001234567890
```

此配置只改变入库通知的投递位置；订阅等交互继续在与机器人的聊天中进行。频道成员可以看到通知中的片名、集数及媒体服务器观看链接，请按频道受众设置访问权限。频道不可写时会记录投递错误，不回退到请求聊天；通知状态仍按原有策略先保存再发送，发送失败不会自动补发。

频道 `chat_id` 格式和发布权限依据 [Telegram Bot API](https://core.telegram.org/bots/api#sendrichmessage)。

## 部署（Docker）

```sh
cp compose.example.yaml compose.yaml   # 填入 API Key、Bot Token、白名单
mkdir -p data && sudo chown 65532:65532 data
docker compose up -d --build
```

镜像基于 `distroless/static`（约 15 MB），以 uid 65532 运行，数据目录挂载到 `/data`。示例使用 host 网络，以便访问同机的 MoviePilot（`127.0.0.1:3001`）。

## 架构

```
cmd/crychic          读取配置，启动
internal/app         组装依赖（main 与 e2e 测试共用）
internal/flow        与平台无关的会话状态机：搜索 → 选择 → 选季 → 确认 → 订阅
internal/moviepilot  精简的 MoviePilot v3 API 客户端（实现 flow.Backend）
internal/telegram    把 flow.Reply 渲染为消息与 Inline Keyboard
internal/notify      记住请求，轮询 MoviePilot 整理记录，入库后通知请求人
internal/config      环境变量配置
```

聊天适配器通过共享的 `flow.Conversation` 驱动会话，通过 `notify.Sender` 投递入库通知；平台负责输入和渲染，业务流程不依赖 Telegram。Discord 尚未实现。

## 改进计划

[MoviePilot API 功能改进计划](docs/plans/moviepilot-api-improvements.md)记录了实施顺序和验收边界。第 1 项已接入可选 Cookie、非 Agent 资源搜索流和搜索前站点选择；第 2 项已接入订阅条件编辑。个人请求、处理进度流等后续条目及高级组合筛选仍未实现。

## 测试

行为优先的端到端测试（参考 [yetone/magpie](https://github.com/yetone/magpie)）。`e2e/` 用与 `main` 相同的组装方式启动真实应用，外部替换为 Telegram、MoviePilot、Bangumi 和图片服务 fake。MoviePilot fake 分别校验 API Key 与合成资源 Cookie，流式场景覆盖分片、批次、断线、凭据隔离及退出；两分钟总预算场景使用真实计时，不增加生产测试开关。

每个场景把跨越边界的全部交互（用户动作、MoviePilot 请求、Telegram 调用）按顺序记录下来，与 `e2e/testdata/transcripts/` 中已提交的记录逐字比对。这些记录本身就是可审阅、可复现的行为规格。

```sh
go test ./...                    # 运行
go test ./e2e/ -update           # 行为有意变更后重新生成记录，审阅 diff 后提交
```

`e2e/testdata/moviepilot/` 大部分 fixture 是 MoviePilot v3.1.0 的裁剪录制；流式搜索、订阅条件更新和规则目录使用官方 v3.1.1 源码约束的合成数据，不通过真实搜索或写入制造录制。
