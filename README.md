# Crychic

以 [MoviePilot](https://github.com/jxxghp/MoviePilot) 为后端的聊天机器人，在 Telegram 中搜索影视并创建订阅。交互流程参考 [Doplarr_rs](https://github.com/activexray/doplarr_rs)。

当前范围：Telegram、订阅与选种下载、白名单权限。白名单内的用户同等管理 MoviePilot 的全部订阅与下载；按用户隔离要等 MoviePilot 官方支持按用户的 API 凭据后再做。Discord 计划中。

## 使用

私聊直接发送片名即可搜索。和 MoviePilot 自带的机器人一样，片名前可以加「订阅」「搜索」或「下载」（后面跟空格或冒号也行，比如 `下载：沙丘`）：前两个和直接发片名一样；「下载」在你选定电影或某一季后直接开始搜索资源，跳过订阅确认，结果页的「返回」回到那张卡片。`/search` 后面同样可以带这些前缀。`/start` 打开首页，所有功能都有入口；也可以直接用命令：

```
/search 沙丘
```

正在等待起始集数时，普通文字优先作为回答，支持 `5`、`５`、`第5集` 等写法；发送 `/search 新片名`、`/start`、`/trending` 等有效命令会清除旧提问并切换流程。群聊仍通过命令操作，输入回答时需要引用机器人的问题。

群聊中明确发给其他机器人的命令不会被 Crychic 接管。话题群里的回复和输入提示保留原话题；原生通知按 MP 提供的明确目标与话题发送。

所有页面的按钮遵循同一套约定：最后一行是导航；每屏唯一提交写入的按钮带颜色，确认类为蓝色，删除、取消订阅等破坏性确认为红色。「返回」回到上一屏；从列表（搜索结果、榜单、相似推荐、同系列、演职人员作品、条件找片结果）里选中再订阅或下载的，完成后的消息也有「返回」，直接回到选片的那一页接着逛；「取消」结束正在进行的搜索、订阅或下载；浏览类页面（订阅、任务、榜单、追剧日历、最新入库）用「首页」回到首页、「关闭」收起消息。删除、取消订阅这类不可撤销的操作会先单独确认。私聊里放置超过 10 分钟或机器人重启后，旧消息上的「首页」「关闭」、首页功能按钮和订阅、任务、发现的返回与分类切换按钮会在原消息里重新打开对应页面；群聊和其他按钮仍提示过期。

选择搜索结果 → （剧集）选择季和起始集 → 确认订阅。已订阅的媒体会提前结束流程，暂停中的订阅会明确标出“目前已暂停”，不会自动恢复。剧集也可以点「多选季…」一次勾选多季，每季从第 1 集开始订阅，已在订阅中的季会跳过（仍会通知）。

TMDB 剧集的选季页有「剧集组…」：列出这部剧在 TMDB 上的其他分季编排（如绝对顺序、故事线、制作顺序），只显示确实编排了季和集的组。选中后按该组的季号和集数选季、定起始集并确认，订阅会带上剧集组，之后的集数计算和资源匹配由 MoviePilot 按该编排处理。媒体库、下载进度和「只追新集」按标准分季记录，所以剧集组下请到媒体库与 `/tasks` 核对；搜索资源、选择搜索站点、洗版订阅和多选季在剧集组下暂不提供，需要时回到标准分季。

搜索结果每页最多 8 条，可翻页查看全部返回结果；已订阅的电影和剧集季会在结果里标出「已订阅」「已暂停」，选季表也多一列「订阅」；选片后返回会恢复原来的页。只有一个结果时直接打开媒体卡片，只有一个常规季且没有特别篇时省去选季，但最终订阅仍需确认。点「重新搜索」可以在原消息中换片，旧查询的按钮随之失效；没有结果时可以直接回复新的片名。换名纠错会保留原来的下载意图，显式加“搜索”或“订阅”可以改回普通流程；进入“相似推荐”或“同系列”选择其他作品则先显示普通卡片，需要你主动点“搜索资源”。

搜索、季信息或已有订阅查询失败时，可以在原消息中点「重试」，保留已经选好的媒体和季；也可以重新搜索、返回上一步或取消。重试只重复失败的查询，不会创建订阅。等待输入的请求过期后，私聊直接发送的片名会立即开始新搜索；明确引用旧提问的回答只提示过期。连点确认不会重复提交，也不会把刚显示的成功结果改成过期提示。

订阅被 MoviePilot 明确拒绝时会显示原因。提交后遇到网络或响应异常，或者没有收到有效的订阅 ID，会提示先用 `/subscribe` 核对结果，不自动重发；旧确认按钮也不能再次提交。

机器人会通过 MoviePilot 查询媒体服务器（Emby/Jellyfin/Plex）里已有的内容：已在库中的电影和整季不会重复订阅；季按钮会标出「已入库」或「已有 N 集」，部分入库的季在确认时列出已有的集（MoviePilot 订阅只下载缺少的集）。选定后还会显示下载器里对应任务的进度。

想要更好的版本时，点卡片上的「洗版订阅」：电影确认页、季的起始集选择页，以及已经在媒体库里的电影或整季都有这个入口。确认后 MoviePilot 会按订阅规则的优先级持续寻找更好的版本，下到最高优先级为止，媒体库里已有的也会重新下载；剧集洗版整季，不用选起始集。已经有订阅的媒体不会再新建洗版订阅（MoviePilot 会直接沿用原订阅）；自己的订阅可以在 `/subscribe` 的详情中点「编辑条件」修改洗版模式。通知由 MoviePilot 的原生设置决定，Crychic 只负责展示和投递。

媒体库查询失败时，卡片会显示「媒体库状态暂时无法确认」，仍可手动确认订阅。详情、海报和下载进度不可用时也不会阻断订阅流程。

选定电影或某一季后，卡片上有「搜索资源」，MoviePilot 按媒体来源、ID 和季去各个站点搜种，通常要几十秒，消息会显示等待时间，搜索期间可以随时「取消」。想限定搜索范围，可先点「选择搜索站点」，勾选后点「开始搜索」；不选则使用全部可搜索站点。资源列表的「排序与筛选…」里可以切换排序（默认、做种、时间、大小、站点）、只看缺集，并用「筛选站点」「组合筛选」只筛选已经返回的资源，不再访问站点；点「返回」回到按新条件排好的列表。

结果默认按 MoviePilot 的优先级排列，也可以在「排序与筛选…」里改按做种数、发布时间、大小或站点排序。某一季媒体库里已有部分集数时，资源会标出能补哪些集或「已都有」，「只看缺集」隐藏不补缺的资源。「组合筛选」可以按分辨率、编码、制作组、大小、促销和 H&R 同时筛选：同一项可多选，不同项同时满足，没标注的值显示为「未知」，每个选项旁标出选上后的资源数。这些操作都在已有结果里进行，不再访问站点。每页最多 8 条，点编号看详情，再点「确认下载」。多选可以跨页、换排序和筛选保留，最多 20 个；「下载所选 N 个」会列出资源和总大小，确认后逐个提交并给出回执。站点 Cookie 和下载链接只在内存中转交，不显示或写入日志。下载结果不确定时先用 `/tasks` 核对，机器人不会重发。

### 缺集下载方案

选定电视剧的一季并等资源搜索完成后，点「缺集方案」，机器人会重新读取媒体库和季总集数，从当前站点筛选后的全部结果中建议补集组合，不局限于当前页，也不重新搜索站点。若已指定起始集，所需范围从该集算到季末；最多支持一季 100 集、一次 20 个资源。

建议优先覆盖更多缺集，同覆盖时优先没有 H&R 标记、重复集数更少、已知且较小体积的资源，最后沿用 MoviePilot 的优先级。显示排序不会改变这套偏好。方案会列出预计可补、仍缺、重复已有、资源间重叠、起始集以前的额外集数、总大小及风险；这只是确定性建议，不保证全局最优。

只纳入同媒体、明确同季且有可信非空识别集数的资源。未知整包、描述推断、多季、特殊剧集组和越界集数留给人工核对，不猜测完整覆盖。识别范围不是种子文件清单；确认下载的是**整个资源**，不会自动裁剪已有或重叠文件。未知大小不计作零体积，免费也不代表免保种。

「重新计算」只读库存与季信息；「确认下载」会再核对一次，库存或季集范围变化时先更新预览，必须重新确认。读取失败时不提交。MoviePilot 返回空库存时会提示先核对媒体库连接及扫描状态，因为上游可能把某些内部故障也表现为空结果。预检不能保证后端在之后不再变化，方案也不计入尚未入库的下载任务。

确认后复用下述串行批量提交、停止后续和逐项回执。方案只保留在当前会话，重启不会恢复或重放。

### 流式资源与批量提交

配置有效的资源 Cookie 后，搜索结果会逐步出现。早期候选尚未匹配媒体，只能浏览；完整最终结果到齐后才开放下载。流式列表的编号固定对应原资源，排序后可能不连续，重新搜索也不复用旧编号。进入详情会停止自动改页，可点「刷新结果」读取最新状态；被最终结果移除或改变的资源必须返回列表重新选择。断线、认证失败或两分钟总预算耗尽时会标明结果不完整，不自动重连，也不改发一次 JSON 搜索。「重新搜索资源」会再次访问站点。取消或返回媒体卡片会关闭本地流，但无法保证 MoviePilot 已发出的每个站点请求立即停止。

下载与整理的通知由 MoviePilot 产生；Crychic 不另发到货或停滞提醒。上游集数识别不可靠时，列表和详情标注“集数识别不确定”，不会把整季包误写成单集。

批量确认后会立即显示“正在提交 N/M”，逐项通过 MoviePilot API 提交。可点“停止后续提交”：当前一项等待结果或超时，后面的不再提交，已创建的下载不会被暂停或删除。该页面结束前保留进度和停止按钮，仍可发送新命令使用其他功能。这里显示的是提交进度，实际下载百分比请看 `/tasks`。重启不会重放未提交或结果不明的请求，应先用 `/tasks` 核对。

### MoviePilot 原生通知

安装仓库内的 Crychic MP 插件，在 MP 通知设置中新增「自定义」渠道，类型填写 `crychic`，选择通知类型并启用。管理员、操作用户及发送时段继续由 MP 原生设置决定。插件页面配置该渠道的默认 Telegram 目标和话题；个人目标使用 MP 用户资料中的 Telegram 绑定。

不需要新增 MP 机器人，也不要在 MP 中配置 Crychic 的 Telegram token 或启动另一个更新接收器。现有 Go 机器人使用原来的 MP 地址和 API key，专用长轮询接收通知，并按当前富文本形式展示标题、正文、图片和链接。插件未安装、停用或不兼容时仅停止通知和整理百分比，其他功能继续工作。

插件的自有数据库保存待消费通知的安全投影，普通重启继续读取。Go 的 `native-notifications.json` 只保存接入身份和进度，不保存正文。首次接入建立基线，不广播此前消息；先保存一次投递尝试再发送，发送结果未知不自动重放，因此进程在这两步之间退出时可能漏发。确认只表示消费，不代表媒体业务完成或 Telegram 成功。

Crychic 不再保存请求归属或最近完成，也不再合并到货、等待媒体库可见、计算通知完成、提醒停滞或发送周报。旧部署数据目录里的 `requests.json` 和 `requests.json.pre-native` 不再读取，原样保留作回退材料。安装、协议和回退步骤见 [插件说明](plugins.v3/crychic/README.md)。

浏览 TMDB 流行趋势、豆瓣热门电影/剧集、正在热映和新番放送表（按周几分页，默认今天）。选中一部会自动找到对应的 TMDB 条目进入订阅流程（续作如「青之芦苇 第二季」也对得上，直接进第 2 季）；豆瓣/Bangumi 条目对不上时让你在搜索结果里挑。条目搜不到或查询失败时仍可返回原榜单。

榜单菜单里的「条件找片」按 TMDB 数据找电影或电视剧：在同一页依次选题材、原始语言、最低评分、最少评分人数、上映时间（近 1/3/10 年）和排序（热门、评分最高、最新），点「开始找片」列出结果，「更多结果」继续读取下一页，已列出的作品保持原编号。没有结果时条件保留，可以放宽后再找；「返回」回到条件页。豆瓣和 Bangumi 的发现接口只支持标签、分类和年份，没有评分与日期条件，因此条件找片目前只用 TMDB。

电影卡片的「同系列」会标出每部的状态：已入库、下载中、已订阅、已暂停订阅或未获取；订阅或下载列表读取失败时显示「状态未知」，这些作品不能勾选。有未获取的作品时可以点「补齐缺少的作品…」勾选，「订阅所选 N 部」逐部订阅（已在订阅中的跳过），结果按作品列出。

媒体卡片上的「演职人员」列出 TMDB 的演员阵容或 Bangumi 的配音演员（附角色名），点编号查看此人的作品，再点编号像榜单条目一样进入订阅流程。Bangumi 的作品列表包含 CD、演出等条目，同一作品只列一次；对不上可订阅条目时会直接说明。

```
/subscribe
```

按电视剧、电影分开列出 MoviePilot 的影视订阅（不混入音乐或未知类型）（状态、缺几集），用按钮切换。每个订阅（包括在 MP 网页端创建的）都可以用「取消订阅」选出来取消，通知由 MP 当前状态与原生设置决定。已结束的订阅在「订阅历史」里，按电视剧、电影分开从新到旧列出，显示总条数；「更多历史」每次再从 MoviePilot 读取更早的 10 条接在后面，编号不变，可以按原来的设置重新订阅。

点编号打开订阅详情，查看起始集、规格、规则组，以及最近一次搜索的状态和时间（北京时间）。「刷新」重新查询，「返回」恢复原来的订阅列表页，不会触发补搜或下载。订阅详情里可以「暂停订阅」（MoviePilot 暂时不再为它找资源），暂停后按钮变成「恢复订阅」；改完会重新读取订阅，显示最新状态；返回列表也会刷新状态并保留原来的类别和页码。MoviePilot 拒绝时转达它的原话，结果不明时提示点「刷新」核对，不会自动重试。

详情把媒体库状态与下载、整理进度分列展示，相同状态的连续集数合并成一行。下载百分比是关联任务的整体进度；整理完成不等于媒体服务器已经可见，MoviePilot 的待获取集数也不等于尚未入库的集数。查询失败显示未知；没有执行记录时不会猜测原因。每次最多展示请求范围内的前 100 集，每页最多 20 行，超出部分明确提示。详情不展示资源名、站点、下载器或文件路径，后台执行错误只提示到 MoviePilot 查看。

### 编辑订阅条件

打开 `/subscribe` → 选择订阅 →「编辑条件」。可调整分辨率、资源类型、画面格式、已有规则组、订阅站点、包含与排除关键词、电视剧起始集，以及普通／洗版模式；电视剧还可以选择分集洗版或全集洗版。不创建新规则组，不改变媒体身份、季或剧集组。

所有修改先留在当前会话的草稿里，菜单标出已修改项和未保存项数，字段页显示当前值，点「恢复原值」只撤回当前一项。「查看修改」列出改动，点「确认保存」才会写入 MoviePilot。从字段页返回保留草稿；有改动时，从编辑菜单返回或取消会先询问是否放弃，点「返回」继续编辑，点「放弃修改」才丢弃草稿。无改动则直接离开。重启或会话过期不会保存草稿。

只提交实际改动字段，不覆盖下载器、路径、调度周期、已取得集数、缺集数或现有洗版优先级。保存不会主动补搜；后台后续调度可能按新条件搜索下载。

规则组和站点支持多选、分页，完成选择和返回都会把勾选保留在草稿中。空规则组沿用全局设置，普通订阅与洗版使用各自的全局规则组；空站点选择沿用 MoviePilot 的默认订阅站点。目录读取失败不清空原设置，选中的规则定义或站点变化时保留其他草稿，重新选择变化的目录项后再确认。

包含与排除条件接收**字面关键词**，用 `|` 分隔候选，任一匹配，最多 256 字、12 项。例如 `简体|CHS`；`[Group]`、`.`、`+` 等按原字符匹配，不作为正则运算符。原有后台正则保留但不在聊天中展开；复杂正则继续在 MoviePilot 中维护。不要输入凭据、链接或服务器路径。

保存前重新核对媒体身份、创建时间和条件快照。后台条件已经变化时保留草稿，列出差异；同一字段有冲突时，逐项选择「保留草稿」或「采用后台」。点「完成处理」接受最新后台值和保留的草稿，再重新确认保存。未修改的字段沿用后台新值；后台再次变化时重新处理，不自动合并或写入。

保存回执提供「核对结果」，对本次修改逐项显示“已生效”“仍为原值”“已变为其他值”或“暂时无法确认”，包含站点及包含／排除条件。核对只读，不重试写入，也不把结果摘要恢复为草稿。敏感表达式不展示；当前值相同不能证明当时请求一定成功。摘要仅在当前会话内存保留，重启或会话过期后应在 `/subscribe` 或 MoviePilot 后台核对。

这个预检不能代替后端原子比较并写入，预检后仍可能有外部并发修改。编辑后的请求核对范围会跟随起始集和洗版模式，不会把略过的集数当作已经入库；通知仍由 MP 原生设置决定。

该功能按 [MoviePilot v3.1.1 更新接口](https://github.com/jxxghp/MoviePilot/blob/v3.1.1/app/api/endpoints/subscribe.py#L299-L379)核验；不需要资源 Cookie，也不新增配置项。更旧版本的部分更新和清空语义未验证，不应假定相同。

### 立即搜索订阅与执行跟踪

在 `/subscribe` 中打开订阅，点「立即搜索」，核对提示后再点「确认搜索」。这会访问站点，并可能按执行时的订阅条件自动下载资源。保存订阅条件本身不会搜索；修改后可先刷新详情，再主动发起一次搜索。确认前条件或暂停状态变化时，会更新提示，要求重新确认。

新建批次会在同一条消息中显示排队、搜索、匹配、提交下载和结束等状态，默认自动刷新，最多跟踪 10 分钟。「刷新」只查询状态，「停止刷新」只停止自动查询。搜索结束不代表找到了资源、下载完成或媒体库可见，实际下载和到货情况仍在 `/tasks` 与订阅详情中核对。

「停止本次搜索」需要再次确认，只控制你在当前会话明确发起、且能核实为同一订阅的新建批次。后台把请求合并到已有批次时，机器人不会接管它；批次范围不明也不开放停止操作。停止成功的回执只表示请求已受理，最终状态要刷新核对，**已提交的下载不会撤销**。暂停订阅不会停止已受理的搜索；对暂停中的订阅确认手动搜索，也不会恢复自动订阅。

当前会话仅保留最近一次搜索回执，可从对应订阅详情点「查看本次搜索」。返回、关闭页面、会话过期或重启机器人都不会停止 MoviePilot 的后台搜索；重启不恢复控制权，也不重放搜索或停止请求。提交结果不明时不提供写入重试，先到 MoviePilot 或用只读页面核对。

不新增配置，不需要资源 Cookie。已核对 MoviePilot `v3.1.1` 和 `v3.1.3` 的提交、批次读取与停止接口，具体契约与版本差异见[接口参考](docs/agent-reference/moviepilot.md#单订阅搜索与执行批次)。源码与端到端 fake 验证不替代目标部署的实机验收。

### 下载任务

```
/tasks
```

列出 MoviePilot 下载中和整理中的任务（只含 MoviePilot 添加的下载）。选中一个任务后，消息会自动刷新进度，直到任务结束、按「停止刷新」或刷新满 10 分钟（可「继续刷新」）；任务页的「返回」会重新读取任务列表，任务全部结束后仍保留“首页”和“关闭”。整理任务显示每个文件的状态；安装 v1.2.0 及以上的 Crychic MP 插件后，复制、移动或上传网盘中的文件会在状态后显示百分比（如「▶️ 整理中 38%」）。硬链接整理没有百分比；插件未安装、版本较旧或无法唯一对应文件时只显示状态。整理完成后媒体服务器可能还需要扫描才可见。

任务列表分别处理下载、整理的查询结果：一路查询失败仍展示另一路成功结果，并注明暂时无法确认的部分，提供「刷新」。只有两路查询都成功且为空时，才会显示没有任务。

下载任务页可以「暂停下载」或「恢复下载」，确认后通过 MoviePilot 控制该任务所在的下载器；已下载的部分保留，回执后点「查看任务」核对下载器里的实际状态。确认时会重新读取任务，任务已结束或已经是目标状态时只更新显示。使用 Transmission 时，暂停的任务会离开下载中列表，恢复请到 MoviePilot 或下载器中进行。

下载任务页有「删除任务」，确认后 MoviePilot 会删除任务**和已下载的文件**。如果同一部片（同一季）还有订阅，确认页会提醒：订阅下的任务删掉后，MoviePilot 已把这些集记为已获取，订阅不会自动重新下载。Crychic 不从删除结果推断后续原生通知。

会话消息编辑遇到临时投递失败时，会重试尚未显示的结果，包括订阅、下载的成功回执；不会重新执行搜索或写操作。重试最长持续 10 分钟，并遵守 Telegram 的限流等待。接受新的导航后停止旧结果重试。新消息发送结果未知时不会自动重发，避免重复消息。

从白名单移除用户并重启后，原生个人通知不再投递给该用户；MP 明确指定的频道通知不增加请求者身份。

新番页先把已有的内容马上显示出来，TMDB 身份和简介在后台补充，补好后原消息自动更新并显示「简介补充中…」的进度；找到的简介会记住几个小时，切换星期时不再重复查询，打开新番放送时还会提前补好一周的简介。简介优先使用 TMDB 和 MoviePilot API，仍为空或失败时才在剩余时间内回退 Bangumi 公共 API；星期分组继续使用完整的 Bangumi 放送日历。

### Inline 模式

在任意聊天的输入框里输入 `@机器人用户名 片名`（至少 2 个字），会弹出带海报的候选列表；选中一条就把一张简短卡片（片名、年份、类型、评分、详情页链接）发到当前聊天，卡片上的「在机器人里打开」会跳到和机器人的私聊，直接打开这部片的卡片，接着订阅或搜资源。只有白名单用户能看到结果。分享出去的卡片是普通 HTML 消息（inline 结果发不了 rich message）。

需要先在 BotFather 里对机器人执行 `/setinline` 开启 inline 模式。

## 配置

全部通过环境变量：

| 变量 | 必填 | 说明 |
| --- | --- | --- |
| `CRYCHIC_MOVIEPILOT_URL` | 是 | MoviePilot 地址，如 `http://moviepilot:3000` |
| `CRYCHIC_MOVIEPILOT_API_KEY` | 是 | MoviePilot 设置中的 `API_TOKEN`，以超级管理员身份调用 |
| `CRYCHIC_MOVIEPILOT_COOKIE` | 否 | 仅填名为 `MoviePilot` 的资源 Cookie 值；启用资源搜索 SSE。留空保持 API Key JSON 搜索，无自动登录或续期 |
| `CRYCHIC_TELEGRAM_TOKEN` | 是 | BotFather 发放的 Bot Token |
| `CRYCHIC_TELEGRAM_ALLOWED_USERS` | 是 | 允许使用的 Telegram 用户 ID，逗号分隔。陌生人使用时机器人会回复其 ID |
| `CRYCHIC_TELEGRAM_API_URL` | 否 | 自建 Bot API 服务器地址，默认 `https://api.telegram.org` |
| `CRYCHIC_BANGUMI_API_URL` | 否 | Bangumi API 地址，默认 `https://api.bgm.tv`；新番放送按周几读取它的每日放送 |
| `CRYCHIC_DATA_DIR` | 否 | 数据目录，默认 `data`，保存原生通知投递进度 |
| `CRYCHIC_NOTIFY_INTERVAL` | 否 | 原生通知接入失败后的重试间隔，默认 `1m`；正常接收使用长轮询 |
| `CRYCHIC_PROGRESS_INTERVAL` | 否 | 任务和资源搜索列表的刷新间隔，默认 `5s`；流式首批结果与终态及时显示，中间事件不逐条刷屏 |

```sh
go build -o crychic ./cmd/crychic && ./crychic
```

### 可选资源 Cookie

由部署者通过受控环境注入 `CRYCHIC_MOVIEPILOT_COOKIE`，只接受单个未加引号的令牌值，不接受 `MoviePilot=...`、整段 Cookie 头、换行或额外 Cookie 项。Cookie 只发到配置源站的资源搜索 SSE 路径，所有重定向都拒绝，不与其他服务共享 Cookie jar。公开域名必须用 HTTPS；私有或回环 IP、Docker 单标签服务名可以使用 HTTP。地址不得带用户名密码、查询参数或片段。

MoviePilot 会校验令牌的资源用途和身份，API Key 或普通登录 JWT 不能改名充当该 Cookie。认证失败时普通 API Key 功能仍可用；管理员安全更新 Cookie 后重启，或移除该变量恢复 JSON 搜索。不要在聊天、日志或提交中粘贴凭据，也不要把真实值写入 compose 示例。依据为 [MoviePilot v3.1.1 认证源码](https://github.com/jxxghp/MoviePilot/blob/v3.1.1/app/adapters/web/security/access.py#L176-L301)。

### 原生通知目标

默认目标及话题由 MP 插件页面设置，个人绑定由 MP 用户资料管理；现有机器人需要具有目标聊天的投递权限。旧频道变量只给出迁移提示，不覆盖 MP 目标。失败不会改发请求聊天。

## 部署（Docker）

```sh
cp compose.example.yaml compose.yaml   # 填入 API Key、Bot Token、白名单
mkdir -p data && sudo chown 65532:65532 data
CRYCHIC_VERSION="$(git describe --tags --always --dirty)" docker compose up -d --build
```

`CRYCHIC_VERSION` 写入二进制与镜像标签，启动日志会打印；省略时为 `dev`。`docker run --rm crychic -version` 可查看镜像版本。

镜像基于 `distroless/static`（约 15 MB），以 uid 65532 运行，数据目录挂载到 `/data`。示例使用 host 网络，以便访问同机的 MoviePilot（`127.0.0.1:3001`）。

## 架构

```
cmd/crychic          读取配置，启动
internal/app         组装依赖（main 与 e2e 测试共用）
internal/flow        与平台无关的会话状态机：搜索 → 选择 → 选季 → 确认 → 订阅
internal/moviepilot  精简的 MoviePilot v3 API 客户端（实现 flow.Backend）
internal/telegram    把 flow.Reply 渲染为消息与 Inline Keyboard
internal/notify      独立接收并投递 MP 原生通知
internal/config      环境变量配置
```

聊天适配器通过共享的 `flow.Conversation` 驱动会话，通过 `notify.Sender` 投递原生通知；平台负责输入和渲染，业务流程不依赖 Telegram。Discord 尚未实现。

## 改进计划

[MoviePilot API 功能改进计划](docs/plans/moviepilot-api-improvements.md)按「现有 Crychic + 原生 API 优先 + MP 插件补足能力」记录实施顺序、能力缺口与验收边界。第 1、2、4 至 11 项已交付，涵盖可选 Cookie 与流式资源搜索、订阅条件编辑、缺集下载方案、单订阅立即搜索跟踪、下载暂停与恢复、整理逐文件进度、条件找片和演职人员作品、按剧集组订阅、同系列库存与补齐，以及完整订阅历史分页；原生通知前置任务已上线验收。

第 3 项个人请求中心及本地请求归属已退役，当前白名单内用户同等管理 MP 的全部订阅与下载。资源结果的高级组合筛选已交付；第 12 项字幕搜索与下载按主人决定暂缓，计划中暂无其他待实施条目。后续功能先核验原生 API，只有存在明确缺口才增加薄插件扩展，不恢复本地归属或自建通知业务。

## 测试

行为优先的端到端测试（参考 [yetone/magpie](https://github.com/yetone/magpie)）。`e2e/` 用与 `main` 相同的组装方式启动真实应用，外部替换为 Telegram、MoviePilot、Bangumi 和图片服务 fake。MoviePilot fake 分别校验 API Key 与合成资源 Cookie，流式场景覆盖分片、批次、断线、凭据隔离及退出；两分钟总预算场景使用真实计时，不增加生产测试开关。

每个场景把跨越边界的全部交互（用户动作、MoviePilot 请求、Telegram 调用）按顺序记录下来，与 `e2e/testdata/transcripts/` 中已提交的记录逐字比对。这些记录本身就是可审阅、可复现的行为规格。

```sh
go test ./...                    # 运行
go test ./e2e/ -update           # 行为有意变更后重新生成记录，审阅 diff 后提交
```

`e2e/testdata/moviepilot/` 大部分 fixture 是 MoviePilot v3.1.0 的裁剪录制；流式搜索、订阅条件更新和规则目录使用官方 v3.1.1 源码约束的合成数据，不通过真实搜索或写入制造录制。
