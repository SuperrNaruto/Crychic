# Crychic MP notification adapter

- 这是 MP 侧薄适配插件，Go 机器人仍是唯一 Telegram 更新接收端。
- 不初始化 Telegram 客户端，不复制通知触发、发送时段或用户路由；接入原生发送阶段并复用宿主检查。
- 只读取选定的 `crychic` 自定义渠道。处理函数返回 None，其他宿主渠道继续执行。
- 插件模块先于系统渠道执行且 strict 调度传播异常；捕获阶段任何失败只停本渠道，不抛回宿主，日志只记固定代码。
- 长轮询与确认的数据库访问放到线程执行，不阻塞宿主事件循环。
- 长轮询先取得入队代次再读快照，事务提交后唤醒；等待使用单调时钟期限，低频数据库复核与断线检查分开。重载关闭旧代等待并复用事务锁，旧请求不得跨代返回内容。
- 队列只持久化安全投影；游标与去重身份独立保存。错误和日志不得包含消息原文或凭据。
- 图片与链接在入队前检查已知凭据、百分号编码和敏感参数；读取时修正旧队列的不安全 URL，保留身份、顺序和业务事实，不清空队列或去重记录。
- 数据库使用插件自有 SDK 句柄，不 dispose 宿主共享引擎。确认只代表消费，不代表业务完成或 Telegram 成功。
- 内部适配点须以目标源码和隔离宿主 E2E 验证；不写单元测试，不用假的 MP 内部类冒充宿主。
- 安装、启用和真实 MP 配置由主人执行，代理不得修改线上插件或自动重载目录。
