# 原生通知 E2E 验收设计

本次替换旧通知业务。先保存本失败清单，再编写实现。每个契约由真实 app 对外部 HTTP fake 的主场景验证，以脱敏 transcript 作为可重复产物；不 mock 内部包。

| 契约 | 失败方式 | 主验收 |
| --- | --- | --- |
| 通知来自 MP | 仅整理事实变化却产生到货、完成、停滞或周报 | 无 MP 通知时保持安静，请求页仍能核对事实 |
| 样式与目标 | HTML 注入、个人消息广播、白名单外接收、话题丢失、敏感 URL | 安全 Heading、正文、图片和链接；原生指定目标不被重路由 |
| 一次投递尝试 | 重复读取、重启重放、ACK 丢失、Telegram 已显示而响应未知 | 先保存尝试再发送，幂等 ACK，不重放未知发送 |
| 基线与范围 | 空基线吞掉首条通知、顺序缺口、来源更换、半响应 | 首次保存基线；不完整范围不推进，机器人仍可工作 |
| 生命周期 | 长轮询退出迟到、停用后投递、第二消费者争抢 | 取消等待并收敛；固定消费身份与排他接入 |
| 兼容与迁移 | 旧 pending 补发、旧配置泄露值、从通知伪造完成 | 保存回退材料；旧业务配置失效 |
| 插件原生行为 | 调度前接入、绕过类型和用户范围、阻断其他渠道、启动 MP Bot | 隔离宿主运行真实插件和原生通知组件，对外部 HTTP fake 验证 |
| 插件持久缓冲 | 重启丢待处理内容、事务失败伪成功、ACK 越过未读取范围 | 插件自有数据库，稳定顺序、独立身份、确认后清理内容 |

旧 quiet、媒体库等待、停滞、周报与合并测试随对应业务退役。2026-10-11 起本地请求归属与到货事实一并退役（见[用户与权限模型](../docs/agent-reference/architecture.md#用户与权限模型)），对应请求记录场景删除；订阅写前的复合身份复核仍由订阅场景覆盖。

## 2026-10-11 插件加固的实施前失败清单

以下清单先于代码保存。主验收仍在真实 MP v3.1.4 隔离宿主，由原生发送入口和认证 HTTP 接口驱动，不替换内部包。URL 场景负责插件落盘边界，现有 Go 场景继续负责渲染和投递边界，避免重复测试。

| 主验收 | 可信失败方式 | 独立行为缺口与产物 |
| --- | --- | --- |
| URL 安全投影 | 已知凭据藏在参数值、路径或 fragment，百分号编码绕过检查，空敏感参数被忽略，畸形 URL 导致整条通知丢失，正常图片和链接被一起删除，旧队列仍保留不安全 URL | 现有宿主仅核验正文脱敏；原生通知经 HTTP 读取并在重载后再次读取，安全 URL 原样保留，敏感或畸形 URL 留空，正文和顺序保留；用真实插件 SDK 数据库注入旧版本的合成持久记录并核对修正，固定 transcript |
| 空闲等待与租约 | 没消息仍反复 SELECT 和写租约，直接返回空批次造成客户端忙轮询，数据库耗时未计入等待期限，续租优化允许另一消费者抢占 | 用 SQLAlchemy 官方事件只观察真实 SQL，不替换执行；固定三秒 HTTP 等待期间进度读取不超过三次、租约更新不超过一次，实际等待保留，第二消费者被拒；预算结论进入 transcript，实测数值另输出 |
| 入队与来源切换 | 读取结束到注册等待之间遗漏唤醒，重复事件不断唤醒，插件重载后旧 HTTP 等待跨代继续，停用或断线后旧线程继续等待或改游标 | 长轮询开始后从原生入口入队，及时返回同一可信消息；重载使旧等待安全退出，新请求继续原顺序；现有 durable 去重与 Go 退出场景继续比对 |

不增加生产测试开关或内部单测。队列及去重记录不自动清理，原有未知发送不重放、独立来源与 ACK 语义保持不变。
