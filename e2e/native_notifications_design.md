# 原生通知 E2E 验收设计

本次替换旧通知业务。先保存本失败清单，再编写实现。每个契约由真实 app 对外部 HTTP fake 的主场景验证，以脱敏 transcript 作为可重复产物；不 mock 内部包。

| 契约 | 失败方式 | 主验收 |
| --- | --- | --- |
| 通知来自 MP | 仅整理事实变化却产生到货、完成、停滞或周报 | 无 MP 通知时保持安静，请求页仍能核对事实 |
| 样式与目标 | HTML 注入、个人消息广播、白名单外接收、话题丢失、敏感 URL | 安全 Heading、正文、图片和链接；原生指定目标不被重路由 |
| 一次投递尝试 | 重复读取、重启重放、ACK 丢失、Telegram 已显示而响应未知 | 先保存尝试再发送，幂等 ACK，不重放未知发送 |
| 基线与范围 | 空基线吞掉首条通知、顺序缺口、来源更换、半响应 | 首次保存基线；不完整范围不推进，机器人仍可工作 |
| 生命周期 | 长轮询退出迟到、停用后投递、第二消费者争抢 | 取消等待并收敛；固定消费身份与排他接入 |
| 兼容与迁移 | 旧 pending 补发、旧配置泄露值、从通知伪造完成 | 保存回退材料；旧业务配置失效 |
| 插件原生行为 | 调度前接入、绕过类型和用户范围、阻断其他渠道、启动 MP Bot | 隔离宿主运行真实插件和原生通知组件，对外部 HTTP fake 验证 |
| 插件持久缓冲 | 重启丢待处理内容、事务失败伪成功、ACK 越过未读取范围 | 插件自有数据库，稳定顺序、独立身份、确认后清理内容 |

旧 quiet、媒体库等待、停滞、周报与合并测试随对应业务退役。2026-10-11 起本地请求归属与到货事实一并退役（见[用户与权限模型](../docs/agent-reference/architecture.md#用户与权限模型)），对应请求记录场景删除；订阅写前的复合身份复核仍由订阅场景覆盖。
