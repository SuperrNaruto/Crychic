# Notifications and request facts

修改通知、游标、持久化、迁移或完成判断前，读取 [通知详情](../../docs/agent-reference/notifications.md)。改文案同时读取 [界面规则](../../docs/agent-reference/flow.md#界面与文案)。

- MP 决定通知种类、事实、时段和受众；Go 只处理传输与语义展示，不自行生成到货、整季完成、停滞、周报或合并通知。
- 原生通知使用独立消费身份、来源与顺序。首次保存基线，普通重启续接；不完整范围不推进，来源变化不自动重置。
- 先原子保存一次投递尝试，再发送；未知结果不重放。ACK 可幂等重试，消费不等于 Telegram 成功。
- Go 进度文件只保存必要身份与进度，正文只在 MP 插件的安全投影队列中持久保存。禁止原始 Message、凭据、敏感路径和未知附件进入日志或队列。
- 个人目标保留现有白名单检查；频道使用 MP 明确目标，不带请求者身份，不回退请求聊天，不解释空目标为全员广播。
- 请求归属与通知解耦。最近完成只从可信完整范围事实保存，最多 50 条；旧状态不回填，洗版与未映射范围不宣称完成，下载使用自身到货而非 Held。
- 请求转移游标仍按完成日期及边界秒全体 ID 推进；读取失败或并发 scope 更新放弃整次转换，不清空事实。
- watch 身份包含订阅行 ID、来源、媒体 ID 和季，身份复用不能继承权限；编辑保存范围不创建请求者。
- 状态未变不重写，必要写入串行。首次迁移先保存旧文件回退材料，不补发旧 pending 或 digest；迁移失败不覆盖原状态。
- 插件不可用只停通知，禁止恢复旧引擎、历史通知轮询或共享系统 SSE。退出必须等待长轮询与发送任务收敛。
